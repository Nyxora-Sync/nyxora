# Contributing to Nyxora Sync

Thank you for your interest in contributing to Nyxora Sync! This project is a free, open-source curriculum for web development and programming languages. We welcome contributions from the community.

## How to Contribute

### 1. Report Issues
Found a bug, typo, broken link, or have a feature request? Open a [GitHub issue](https://github.com/Nyxora-Sync/nyxora/issues).

### 2. Suggest New Content
- **New lessons**: Propose a lesson for an existing track or a new track
- **Resources**: Suggest free, high-quality resources for existing lessons
- **Translations**: Help translate lessons into other languages

### 3. Improve Existing Content
- Fix confusing explanations or outdated code examples
- Add missing context or clarifications
- Improve accessibility or SEO

### 4. Share Your Projects
Submit your projects to the [Community Showcase](https://nyxora-sync.tech/community/showcase) for others to learn from.

## Contribution Process

1. **Fork** the repository
2. **Create a branch** for your changes
3. **Make your changes** with clear commit messages
4. **Open a Pull Request** with a description of what you changed and why

## Content Guidelines

### Lessons
- **Written first**: Every concept must be explained on the page. External links are optional depth, never required reading.
- **Accuracy over volume**: Verify against current documentation. When APIs change, lessons get updated.
- **Runnable examples**: Code should work when copied. Test your examples.
- **No dark patterns**: No fake urgency, no engagement streaks, no selling attention.

### Resources
- Must be **free** and **permanently accessible**
- Prefer official documentation, established educational sites, and reputable community resources
- Avoid paywalled content, trial periods, or content that requires signup

### Code Style
- Follow the existing code style in the repository
- Use TypeScript for all new code
- Ensure `npm run lint:ci` and `npm run typecheck` pass

## Setting Up Locally (for code contributions)

If you're contributing to the *site code* (not just content), you'll need the private development repository. The public repository contains only documentation and community-facing files.

For content-only contributions (lessons, resources, translations), you can edit files directly on GitHub or fork this repository.
