So far every React app has been a single screen. Real applications have many: a home page, a list, a detail view, a settings page, a 404. You could swap components with a `page` state variable — until the back button breaks, URLs stop being shareable, and nothing is bookmarkable.

**Client-side routing** fixes all of that. The URL becomes the state: a route renders the matching component, the browser's back button works, and every screen has an address you can send to a friend.

<Callout type="info" title="Which version?">
  React Router v7 is current; install it as `react-router`. In v6 the package was `react-router-dom`, and most `v6` imports still re-export from `react-router`, so tutorials written for either version work with the code here. The API used in this lesson is the same in both.
</Callout>

## Setup

```bash
npm install react-router
```

Wrap your app once, in `main.jsx`:

```jsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { BrowserRouter } from 'react-router'
import App from './App.jsx'

createRoot(document.getElementById('root')).render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>
)
```

`BrowserRouter` listens to the History API and re-renders your app when the URL changes — no page reloads.

## Routes, links, and layout

Define the route table in `App.jsx`:

```jsx
import { Routes, Route } from 'react-router'
import Layout from './Layout.jsx'
import Home from './pages/Home.jsx'
import Posts from './pages/Posts.jsx'
import PostDetail from './pages/PostDetail.jsx'
import NotFound from './pages/NotFound.jsx'

export default function App() {
  return (
    <Routes>
      <Route element={<Layout />}>
        <Route index element={<Home />} />
        <Route path="posts" element={<Posts />} />
        <Route path="posts/:id" element={<PostDetail />} />
        <Route path="*" element={<NotFound />} />
      </Route>
    </Routes>
  )
}
```

- `index` matches the parent path itself (`/`).
- `path="posts/:id"` declares a dynamic segment named `id`.
- `path="*"` catches everything unmatched — your 404.
- Roads that share a layout are nested under a parent `<Route element={<Layout />}>`.

`Layout.jsx` renders the shared chrome and an **`Outlet`**, where the matched child route appears:

```jsx
import { NavLink, Outlet } from 'react-router'

export default function Layout() {
  return (
    <div className="app">
      <header>
        <nav>
          <NavLink to="/" end>Home</NavLink>
          <NavLink to="/posts">Posts</NavLink>
        </nav>
      </header>

      <main>
        <Outlet />
      </main>
    </div>
  )
}
```

Navigation uses `Link` or `NavLink` — never a plain `<a href>`, which would trigger a full page reload:

```jsx
import { Link, NavLink } from 'react-router'

<Link to="/posts/42">Read post 42</Link>

<NavLink
  to="/posts"
  className={({ isActive }) => (isActive ? 'nav-link active' : 'nav-link')}
>
  Posts
</NavLink>
```

`NavLink` gives you the `isActive` flag so current-page styling needs no extra state.

## Dynamic route params

`useParams` reads the values from the URL:

```jsx
import { useEffect, useState } from 'react'
import { Link, useParams } from 'react-router'

export default function PostDetail() {
  const { id } = useParams()
  const [post, setPost] = useState(null)
  const [status, setStatus] = useState('loading')

  useEffect(() => {
    setStatus('loading')
    const controller = new AbortController()

    async function load() {
      try {
        const response = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`, {
          signal: controller.signal,
        })
        if (!response.ok) throw new Error(`HTTP ${response.status}`)
        setPost(await response.json())
        setStatus('ready')
      } catch (error) {
        if (error.name !== 'AbortError') setStatus('error')
      }
    }

    load()
    return () => controller.abort()
  }, [id]) // re-fetch when the URL id changes

  if (status === 'loading') return <p>Loading…</p>
  if (status === 'error') return <p>Could not load this post.</p>

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
      <Link to="/posts">Back to all posts</Link>
    </article>
  )
}
```

The `id` in the dependency array is the whole point: navigate from `/posts/1` to `/posts/2` and the effect re-runs, because React Router re-renders the same component with a new param.

## Query strings as state

`useSearchParams` reads and writes the query string — perfect for filters, tabs, and pagination, because the state lives in the URL and survives reloads and sharing:

```jsx
import { useSearchParams } from 'react-router'

export default function Posts() {
  const [searchParams, setSearchParams] = useSearchParams()
  const page = Number(searchParams.get('page') ?? 1)
  const query = searchParams.get('q') ?? ''

  function setQuery(next) {
    setSearchParams((current) => {
      const params = new URLSearchParams(current)
      if (next) params.set('q', next)
      else params.delete('q')
      params.set('page', '1') // changing a filter resets pagination
      return params
    })
  }

  return (
    <section>
      <input value={query} onChange={(event) => setQuery(event.target.value)} />
      <p>Page {page}</p>
      <button onClick={() => setSearchParams({ page: String(page + 1) })}>
        Next page
      </button>
    </section>
  )
}
```

<KeyPoint>
Put state in the URL when the user would expect to share it, bookmark it, or reload into it: search terms, filters, sorting, pagination, selected tabs. Keep UI-only state (an open dropdown) in `useState`.
</KeyPoint>

## Redirecting

`useNavigate` navigates from code — after a successful login or form submit:

```jsx
import { useNavigate } from 'react-router'

export default function NewPostForm() {
  const navigate = useNavigate()

  async function handleSubmit(event) {
    event.preventDefault()
    // ...create the post...
    navigate('/posts/42')      // push a new entry
    // navigate('/posts', { replace: true })  // replace the current entry
  }

  return <form onSubmit={handleSubmit}>{/* ... */}</form>
}
```

The `Navigate` component redirects during render, which is how protected routes work.

## Protected routes

A protected route checks auth before rendering the page and redirects to login if needed. First, an auth context (the next lesson covers context in depth):

```jsx
// AuthContext.jsx
import { createContext, useContext, useMemo, useState } from 'react'

const AuthContext = createContext(null)

export function AuthProvider({ children }) {
  const [user, setUser] = useState(null)

  const value = useMemo(
    () => ({
      user,
      login: (name) => setUser({ name }),
      logout: () => setUser(null),
    }),
    [user]
  )

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>
}

export function useAuth() {
  const context = useContext(AuthContext)
  if (!context) throw new Error('useAuth must be used inside AuthProvider')
  return context
}
```

Then a wrapper that remembers where the user was headed:

```jsx
import { Navigate, useLocation } from 'react-router'
import { useAuth } from './AuthContext.jsx'

export function RequireAuth({ children }) {
  const { user } = useAuth()
  const location = useLocation()

  if (!user) {
    // Remember the attempted URL so login can send the user back
    return <Navigate to="/login" state={{ from: location }} replace />
  }

  return children
}
```

```jsx
<Route
  path="dashboard"
  element={
    <RequireAuth>
      <Dashboard />
    </RequireAuth>
  }
/>
```

The login page can read `location.state?.from` and navigate back after a successful sign-in. Using `replace` on the redirect keeps the protected URL out of the back-button history, so “back” from login does not immediately bounce the user forward again.

<Callout type="warning" title="Client-side protection is UX, not security">
  Hiding a route does not protect data. Anyone can call your API directly. Every endpoint must verify the token and permissions on the server — the same `requireAuth` middleware from the Express module. The router guard only decides what to render.
</Callout>

## Data routers: loaders and actions

React Router also ships a “data router” mode where a route declares how to **load** and **mutate** its data, and the router handles pending and error states:

```jsx
import { createBrowserRouter, RouterProvider, useLoaderData } from 'react-router'

async function postsLoader() {
  const response = await fetch('/api/posts')
  if (!response.ok) throw new Error('Failed to load posts')
  return response.json()
}

function Posts() {
  const posts = useLoaderData()
  return <ul>{posts.map((post) => <li key={post.id}>{post.title}</li>)}</ul>
}

const router = createBrowserRouter([
  {
    path: '/',
    element: <Layout />,
    errorElement: <ErrorPage />,
    children: [
      { index: true, element: <Home /> },
      { path: 'posts', element: <Posts />, loader: postsLoader },
    ],
  },
])

createRoot(document.getElementById('root')).render(<RouterProvider router={router} />)
```

Loaders fetch **before** rendering, so components do not need loading states for the initial data. TanStack Query (a later lesson) solves the same problem with caching and background refetches; both are worth knowing. For this curriculum, start with the component-level pattern above, then adopt a data layer as your apps grow.

## Compare the pieces

| Tool | Use it for |
|------|-----------|
| `Link` / `NavLink` | Navigation in markup; never `<a href>` for internal links |
| `useParams` | Read dynamic segments like `/posts/:id` |
| `useSearchParams` | Read/write filters, pagination, and shareable state |
| `useNavigate` | Navigate after an event (login, form submit) |
| `Navigate` | Redirect during render (guards) |
| `Outlet` | Render the matched child route inside a layout |
| `useLocation` | Read the current location, including `state` |

## Summary

- Client-side routing gives your SPA real URLs with working back/forward, bookmarks, and deep links.
- `BrowserRouter` + `Routes`/`Route` map URLs to components; `Link`/`NavLink` navigate without reloading.
- Nested routes with a layout and `Outlet` keep shared chrome mounted across pages.
- `useParams` reads dynamic segments; re-fetch when they change by putting them in the effect's dependencies.
- `useSearchParams` makes filters and pagination shareable and reload-safe.
- `useNavigate` for navigation after events; `Navigate` for redirects during render.
- Protected routes improve UX; the server remains the real security boundary.
- Data routers with loaders fetch before render — a signpost toward TanStack Query.
