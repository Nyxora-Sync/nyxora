## The Brief: "Vendor Dashboard for Marketplace Platform"

> **Client:** "We're launching a 2-sided marketplace connecting local artisans with buyers. We need a vendor dashboard where artisans can:
> - Register and onboard (business details, bank info for payouts)
> - Manage products (CRUD + images + inventory)
> - View orders assigned to them (status updates, shipping)
> - See earnings analytics (daily/weekly/monthly, pending vs. paid)
> - Receive notifications (new order, payout sent, low stock)
>
> **Constraints:**
> - Stack: Next.js 14 (App Router), TypeScript, PostgreSQL, Prisma, Tailwind
> - Auth: NextAuth.js (Credentials + Google OAuth)
> - Payments: Stripe Connect Express (vendor onboarding + payouts)
> - Real-time: Socket.io for notifications
> - Deploy: Vercel (frontend) + Render (API) + Neon (PostgreSQL)
> - Timeline: 5 business days from kickoff
> - Budget: Professional tier ($3,000 equivalent)
>
> **Acceptance Criteria (Non-Negotiable):**
> 1. Vendor can complete onboarding → Stripe Connect account active
> 2. Vendor can create/edit/delete products with images (S3/R2 upload)
> 3. Vendor sees only THEIR orders, can update status (pending → shipped → delivered)
> 4. Earnings dashboard shows correct numbers (tested with seed data)
> 5. Real-time notifications appear without refresh
> 6. 80%+ test coverage (Vitest + Playwright)
> 7. Staging deploy accessible via URL for client review
> 8. Handoff document delivered (access, deploy, maintenance)
> 9. Zero critical/severe vulnerabilities (`npm audit`)
> 10. Lighthouse 90+ on all pages"

## Technical Specifications

### Database Schema (Prisma)
```prisma
model User {
  id            String    @id @default(cuid())
  email         String    @unique
  passwordHash  String?
  name          String?
  role          Role      @default(VENDOR)
  image         String?
  stripeAccountId String?  // Stripe Connect account ID
  onboardingComplete Boolean @default(false)
  createdAt     DateTime  @default(now())
  updatedAt     DateTime  @updatedAt
  products      Product[]
  orders        Order[]   @relation("VendorOrders")
  notifications Notification[]
}

model Product {
  id          String   @id @default(cuid())
  vendorId    String
  vendor      User     @relation(fields: [vendorId], references: [id])
  name        String
  description String?
  price       Int      // cents
  inventory   Int      @default(0)
  images      String[] // S3/R2 URLs
  isActive    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
  orderItems  OrderItem[]
}

model Order {
  id          String     @id @default(cuid())
  buyerEmail  String
  vendorId    String
  vendor      User       @relation("VendorOrders", fields: [vendorId], references: [id])
  status      OrderStatus @default(PENDING)
  total       Int        // cents
  stripePaymentIntentId String?
  createdAt   DateTime   @default(now())
  updatedAt   DateTime   @updatedAt
  items       OrderItem[]
}

model OrderItem {
  id        String  @id @default(cuid())
  orderId   String
  order     Order   @relation(fields: [orderId], references: [id])
  productId String
  product   Product @relation(fields: [productId], references: [id])
  quantity  Int
  price     Int     // cents at time of order
}

model Notification {
  id        String           @id @default(cuid())
  userId    String
  user      User             @relation(fields: [userId], references: [id])
  type      NotificationType
  title     String
  message   String
  read      Boolean          @default(false)
  data      Json?
  createdAt DateTime         @default(now())
}

enum Role { VENDOR ADMIN }
enum OrderStatus { PENDING CONFIRMED SHIPPED DELIVERED CANCELLED REFUNDED }
enum NotificationType { NEW_ORDER PAYOUT_SENT LOW_STOCK SYSTEM }
```

### API Routes (Next.js App Router)
```
POST   /api/auth/register          // Vendor registration
POST   /api/auth/login             // Credentials login
GET    /api/auth/google            // Google OAuth
POST   /api/auth/logout

GET    /api/vendor/onboarding      // Check Stripe Connect status
POST   /api/vendor/onboarding      // Create Stripe Connect Express account
GET    /api/vendor/onboarding/callback // Stripe return

GET    /api/products               // List vendor's products (paginated)
POST   /api/products               // Create product + image upload
PATCH  /api/products/[id]          // Update product
DELETE /api/products/[id]          // Delete product
POST   /api/products/[id]/images   // Upload product images (presigned URL)

GET    /api/orders                 // List vendor's orders (filterable)
PATCH  /api/orders/[id]            // Update order status (vendor)
GET    /api/orders/[id]            // Order detail

GET    /api/analytics/earnings     // Daily/weekly/monthly aggregates
GET    /api/analytics/overview     // Summary cards (revenue, orders, products)

GET    /api/notifications          // List (paginated, filter unread)
PATCH  /api/notifications/[id]/read // Mark read
```

### Frontend Pages
```
/vendor/onboarding          // Stripe Connect flow
/vendor/dashboard           // Overview + earnings summary
/vendor/products            // Product list + create/edit modal
/vendor/products/[id]/edit  // Edit product
/vendor/orders              // Order list + status update
/vendor/orders/[id]         // Order detail
/vendor/analytics           // Charts (Recharts) + date range picker
/vendor/notifications       // Notification center (real-time badge)
```

### Real-time (Socket.io)
- **Server**: Custom Node server on Render (or Pusher/Ably if simpler)
- **Events**: `notification:new`, `order:status_changed`, `payout:sent`
- **Auth**: JWT in handshake query → validate → join `user:{id}` room
- **Client**: `useSocket` hook in `_app.tsx` or layout

## Quality Gates (Must Pass)

### Automated (CI/CD - GitHub Actions)
```yaml
# .github/workflows/ci.yml
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env: { POSTGRES_PASSWORD: test }
        ports: [5432:5432]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4 { node-version: 20 }

      - run: npm run typecheck
      - run: npm audit --audit-level=high
```
